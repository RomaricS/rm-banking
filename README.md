# akwe

*akwɛ* — "money" in Fongbe. An iOS app that links up to 4 banks through Plaid, categorizes every transaction into **pockets**, tracks spending **per pay period**, sets **limits**, and plans **goals** (solo or shared with a partner). English + French, light + dark.

- Feature spec: [`docs/FEATURES.md`](docs/FEATURES.md)
- Implementation log / where to resume: [`docs/PROGRESS.md`](docs/PROGRESS.md)
- Design canvas (flows, screens, motion): https://claude.ai/artifact/H2gQvgcEXUZLpBW9YVKo94

## 1. Try it right away (demo mode, no accounts needed)

```bash
brew install xcodegen
```

```bash
cd ios && xcodegen
```

```bash
open Akwe.xcodeproj
```

Pick an iPhone simulator and run. With `SUPABASE_URL` empty the app starts in **demo mode**: no sign-in, generated sample data (three banks incl. a Canadian card and a La Banque Postale deferred-debit card, goals, a shared goal, bills). Everything is browsable; linking real banks is disabled.

> First build: in **Signing & Capabilities**, select your team for both targets (`Akwe`, `AkweWidgets`). Xcode may ask to register the App Group `group.com.wakalo.akwe`. If the bundle id `com.wakalo.akwe` is taken, change it in `project.yml` (app, widget, App Group in both entitlements, and `AppGroup.identifier` in `AkweKit/WidgetSnapshot.swift`).


In Xcode, ⌘U on the `Akwe` scheme runs the AkweKit tests. CI (`.github/workflows/ci.yml`) runs both suites plus the localization check.

## 3. Backend (Supabase)

1. Create a project at supabase.com (region close to you, e.g. EU or US).
2. Install the CLI and link the project:
   ```bash
   brew install supabase/tap/supabase
   ```
   ```bash
   cd backend && supabase login && supabase link --project-ref YOUR-PROJECT-REF
   ```
3. Push the schema:
   ```bash
   supabase db push
   ```
4. Store the two secrets the scheduled jobs need (SQL editor in the dashboard):
   ```sql
   select vault.create_secret('https://YOUR-PROJECT-REF.supabase.co', 'project_url');
   select vault.create_secret('YOUR-SERVICE-ROLE-KEY', 'service_role_key');
   ```
5. **Auth › Providers › Apple**: enable it and add your app's bundle id (`com.wakalo.akwe`) to *Client IDs*. Native Sign in with Apple only needs the bundle id.
6. Function secrets: copy `backend/supabase/functions/.env.example` to `.env`, fill it in, then:
   ```bash
   supabase secrets set --env-file ./supabase/functions/.env
   ```
   ```bash
   supabase functions deploy
   ```
7. Load two years of exchange rates once (the cron keeps them fresh afterwards):
   ```bash
   curl -X POST "https://YOUR-PROJECT-REF.supabase.co/functions/v1/fx-refresh" -H "Authorization: Bearer YOUR-SERVICE-ROLE-KEY" -d '{"backfill":true}'
   ```

## 4. Plaid

1. Dashboard › Developers › Keys: copy `client_id` and the **Sandbox** secret into `functions/.env` (`PLAID_ENV=sandbox`).
2. Dashboard › Developers › API › **Allowed redirect URIs**: add `https://YOUR-DOMAIN/plaid-oauth` and set `PLAID_REDIRECT_URI` to it. Most European banks (La Banque Postale, Revolut…) use OAuth and need this.
3. Webhook URL is set automatically per link token (`…/functions/v1/plaid-webhook`).
4. Sandbox test login: `user_good` / `pass_good`. For production, request access for **Transactions** in the US, CA and EU (FR) and switch `PLAID_ENV=production`.
5. No domain yet? Leave `PLAID_REDIRECT_URI` empty: Sandbox's non-OAuth test banks work without it. The full production switch (free GitHub Pages domain included) is in [docs/GO-LIVE.md](docs/GO-LIVE.md).

## 5. Apple

- **Sign in with Apple**, **Push Notifications**, **App Groups** (`group.com.wakalo.akwe`) and **Associated Domains** are declared in `project.yml`; Xcode's automatic signing creates them.
- **Push (APNs)**: Certificates, IDs & Profiles › Keys › create a key with *Apple Push Notifications service*. Put its Key ID, your Team ID and the `.p8` contents into `APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_PRIVATE_KEY` (newlines as `\n`). Debug builds register as `sandbox`, release builds as `production`.
- **Universal links** (Plaid OAuth return + shared-goal invites): host `https://YOUR-DOMAIN/.well-known/apple-app-site-association`:
  ```json
  { "applinks": { "details": [ { "appIDs": ["TEAMID.com.wakalo.akwe"], "components": [ { "/": "/plaid-oauth*" }, { "/": "/join*" } ] } ] } }
  ```
  Set `AKWE_LINK_DOMAIN` in `Secrets.xcconfig` and `INVITE_BASE_URL=https://YOUR-DOMAIN/join` in the function secrets. Without a domain, invites fall back to `akwe://join?code=…`.

## 6. Point the app at your backend

```bash
cp ios/App/Config/Secrets.xcconfig.example ios/App/Config/Secrets.xcconfig
```

Fill in `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `AKWE_TEAM_ID`, `AKWE_LINK_DOMAIN`, then `xcodegen` again and run on a device (push notifications need a real device).

## How the money logic works (short version)

- **Sign convention**: amounts are stored from your point of view (negative = money out).
- **What counts as spending**: only `spend` and `refund` (refunds reduce spending). Transfers between your own accounts, credit-card payments and deferred-card month-end lumps are recognised server-side and **not** counted twice.
- **Payment method**: from the account type in the US/Canada; parsed from bank labels in Europe (`CB`, `PRLV`, `VIR`, `RETRAIT DAB`, `CHQ`, `Lastschrift`, UK `DD`/`FPS`…).
- **Pay periods**: detected from your paychecks (weekly / every 2 weeks / twice a month / monthly), editable in Settings.
- **Currencies**: display currency of your choice; balances at today's ECB rate, past transactions at the rate of their date.
- **Goals**: money is never moved. Progress comes from a linked account's balance, an earmark, or amounts you log. Shared goals show your partner the goal, never your transactions.
